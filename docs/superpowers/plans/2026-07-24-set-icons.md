# Set & Scenario Icons (M4-B icons) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill the icon slots the quest-picker already draws (Scenario Options' scenario symbol + each sets-to-gather row) with the real encounter-set / expansion symbols, by rasterizing the community SVG icon pack into device-drawable bitmasks and mapping them to catalog `encounterSet` slugs.

**Architecture:** A build tool rasterizes each SVG to a small 1-bit mask and emits them as **generated data** (`docs/data/icons.json`), not tracked source — the same posture as the card catalog, so no derived artwork lives in the repo. Both twins load that file through the existing catalog-data path (firmware from flash, web by fetch) and draw a mask with the icon-drawing primitive already used for stat icons. A normalizing slug matcher maps catalog sets to icon names, with a documented fallback for misses.

**Tech Stack:** Python stdlib + `cairosvg` and Pillow (both confirmed present on the dev host; `rsvg-convert` is a fallback). Web ES modules + MicroPython. pytest + the scene layout linter.

**Context:** The **B-icons** piece of the M4-B family (see `docs/superpowers/specs/2026-07-24-quest-picker-bcore-design.md` → "M4-B family"). B-core, B-modal and B-sidequest are complete. `ScenarioOptionsScreen` already renders placeholder `icon_slot(...)` squares — this plan replaces their contents.

### Task 1: `tools/build_icons.py` — rasterize to masks

**Files:** Create `tools/build_icons.py`; Test `tests/test_icons.py`.

**Interfaces (Produces):**
- `svg_to_mask(svg_bytes, size=24, threshold=128)` → `[int, ...]` (length `size`), MSB-first per row. Rasterizes with `cairosvg` to a square RGBA bitmap, composites on white, converts to greyscale, and sets a bit where the pixel is darker than `threshold` (ink). Must handle SVGs whose viewBox is non-square by fitting and centring.
- `build(assets_root, out_path)` → writes `{"generated": <date>, "source": <pack provenance>, "size": 24, "icons": {<slug>: [ints...]}}`; slug = filename lowercased with `_`→`-`, `.svg` stripped. Encounter-set and expansion-symbol icons share one namespace (encounter sets win a collision; log it). Returns a summary dict (counts).
- CLI: `python3 tools/build_icons.py [--assets PATH] [--out docs/data/icons.json]`; exits 0 with a clear message if the pack is missing.

### Task 2: Slug matcher + loaders (both twins)

**Files:** Modify `quest_catalog.py`, `docs/js/quest_catalog.js`; Test `tests/test_quest_catalog.py`.

**Interfaces (Produces):**
- `normalize_icon_key(slug)` / `normalizeIconKey` — lowercase, drop a trailing `-nightmare`, remove possessive artifacts (`-s-` → `s-`, trailing `-s` → `s`), strip `the-` prefix, collapse repeated hyphens. (Our catalog slugs come from set names, so misses are mostly apostrophes and a couple of upstream typos.)
- `icon_for(slug, icons)` / `iconFor(slug, icons)` → the mask list or `None`: try the exact slug, then the normalized slug, then the normalized slug of both against normalized icon keys. Never raise.
- `load_icons()` / `loadIcons()` → the `icons` dict from `/data/icons.json` (firmware) or `data/icons.json` (web); `{}` on any failure.
