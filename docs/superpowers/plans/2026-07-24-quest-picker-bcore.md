# Quest Picker (M4-B core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Setup-phase quest-picker flow (Player Setup → Scenario Setup → Pick Cycle → Choose Scenario → Scenario Options → Quest Setup → Round 1), preloading a scenario's stages from the M4-A catalog and performing the pre-round-1 first flip (1A→1B) — replacing today's manual "type quest points" step. Web-first, then firmware in lockstep.

**Architecture:** New pre-game screens returning transition tuples that `main.js`/`main.py` route through; a `gamestate` extension (`scenario` + `stages` snapshot + `stage_idx`/`card_idx`/`side`) that derives quest points from the loaded catalog; catalog index gains `cycle`/`source`/`releaseDate`. Quest Setup reuses the two-zone stats layout. In-game advancement is **out of scope** (B-resolve) — B-core only does the pre-round-1 first flip.

**Tech Stack:** ES modules (web, Canvas) + MicroPython (firmware); Python stdlib for `build_card_data.py`; pytest + the scene layout linter.

**Full spec:** `docs/superpowers/specs/2026-07-24-quest-picker-bcore-design.md` — read it before starting; it carries the six-screen layouts, verified mechanics, and scope. **Layout reference:** `scratchpad/mock_quest.py` renders device-faithful mocks of every screen (exact coordinates, Button ids) — match it.

## Global Constraints

- **Two twins in lockstep** ([[CLAUDE]] Iron rule #1): every change lands in web `docs/js/` first (verified in browser), then the firmware mirror (`gamestate.py`, `main.py`, `ui/`). A task is done only when both twins + tests are green.
- **`python3 -m pytest tests/` stays green** (Iron rule #3), including the scene layout linter. Add a scene per new screen.
- **Never hand-edit** `docs/js/{phases,icons,metrics}.js` (generated by `tools/gen_web_data.py`).
- **Screen contract** (both twins): `draw` rebuilds `this.buttons`/`self.buttons` from scratch; `onButton`/`on_button` returns `null`/`"redraw"`/`true` or a **transition tuple**. Controls pushed before whole-row tap targets (first array match wins hit-test).
- **Transition vocabulary** (router-interpreted, `result[0]`): `"goto"`→screen key, `"modal"`→instance, `"close"`→pop nav, `"start_game"`→build game. New tags this plan adds: `"pick_scenario_source"`, `"choose_scenario"`, `"scenario_chosen"`, `"begin_setup"`, `"flip_to_b"` (see tasks).
- **No drag-scroll.** Long lists reuse the Log pager (`ScreenLog`/`screen_log.py`): `page` field, `PER_PAGE`, Up/Down buttons + "N/M", shown only when `pages>1`.
- **Header:** standard `R0 · title · Set.` (round id left, title centre, settings right) via `drawHeader` (web `screens.js:30`) / `draw_header` (firmware `ui/header.py:21`).
- **Firmware divergences to respect:** modal `draw(self,hw,game,pal)` uniform arity; `wrap_text`/`truncate_text`/`note_panel` take a trailing `measure=d.measure_text`; header helpers live in `ui/header.py`; add new pre-game screen keys to the `active not in (...)` exclusion checks (`main.js:212-267`, `main.py:149-221`).
- **Model spec:** `scenario` = `null|{slug,name,pack,cycle,source,kind,nightmare,mode}`; `stages` = verbatim copy of the catalog `quest.stages`; `stage_idx`/`card_idx`/`side` index into it; `quest.points` derives from `stages[stage_idx].cards[card_idx].questPoints`. `scenario==null` → today's manual flow, unchanged.

    def preload_scenario(self, scn, stages):
        import copy
        self.scenario = scn
        self.stages = copy.deepcopy(stages)
        self.stage_idx = 0; self.card_idx = 0

        card = self.stages[self.stage_idx]["cards"][self.card_idx]

        return self.quest["points"]
