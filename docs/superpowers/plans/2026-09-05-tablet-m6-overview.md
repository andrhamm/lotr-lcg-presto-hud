# Tablet milestone 6 — Overview and picker — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new game is picked source → cycle → scenario at tablet density, lands on a **Scenario overview** (set icon and title, difficulty ladder, sets to gather with icons, stages with points, the scenario's own cards as images with counts, shared sets as chips, notes with sources) whose one CTA is **Begin setup**; the same overview opens read-only from the QUEST zone's stage name during play.

**Architecture:** Two pure renderers (`newgame.js` reworked; `overview.js` new) and two acts modules (`acts_newgame.js`, `acts_overview.js`); `app.js` keeps the two async steps it already owns (`pick_scenario` loads the bundle, `begin_setup` seats the game). The catalog grouping stays the twin's (`groupByCycle`/`cyclesFor`), the difficulty ladder is the twin's `difficultyOptions()` logic ported as a pure function, and the mode tips move to `viewcopy.py` so both twins read one text. Milestone 5's `setIcon`, `cardImage`, `stagePointsShape` and `allNotes` are reused, never re-implemented.

**Tech Stack:** ES modules, `tools/gen_web_data.py` for the copy move, pytest driving node.

**Spec:** `docs/superpowers/specs/2026-09-05-tablet-client-design.md` — "Modals and full screens" (Scenario overview row; "The picker flow (source → cycle → scenario) reuses the branch's screens' content at tablet density; it is a list, not a design problem"), "Tap economy", "Visual system".

## Global Constraints

- Never ship an unverified rules claim: the difficulty tips are the twin's already-shipped `TIP_TEXT` sentences (verified in CLAUDE.md "Easy mode is general, and it is TWO steps" / "Nightmare is a swap"); a printed Mode card's text comes from the catalog (`data.modes[].faces[].text`); Hard/Epic are gated on the catalog's per-scenario `modes` exactly as the twin gates them. No new sentence about the game.
- Generated mirrors: `docs/js/viewcopy.js` is regenerated by `tools/gen_web_data.py` from `viewcopy.py` — never hand-edited; `tests/test_viewcopy.py` byte-compares.
- Web first, then firmware, in lockstep: moving `TIP_TEXT` into `viewcopy.py` changes both twins' source of the text (the JS screen imports it; the Python screen — find it — reads `viewcopy.MODE_TIPS`); a parity test asserts the strings are identical.
- Pure renderers via `h`` `/`raw()`; nested `h` through `raw`; only `app.js` touches the DOM/`db`; BODY for anything read as a sentence/name/option, LABEL for chrome; sizes on 34/20/18/13; ≥44px targets; tokens gate covers new button classes by name.
- The picker excludes `kind === "nightmare"`, ` - Nightmare` names and zero-stage entries (that is `groupByCycle`'s own filter — reuse it).
- The common round stays at 20 taps; a new game is at most **4 taps** from the New game screen to Begin setup with the default source (cycle, scenario, Begin = 3; +1 when switching source).
- `db.bundle(slug)` remains the one catalog read per game; the overview reads `ui.overview.bundle`, never fetches.

## Rulings made while planning

- **R1 — Default source is Official**, preselected; "Community" is one chip away (the twin makes the source a full screen; on the tablet it is a two-chip toggle above the cycle list).
- **R2 — Cycle → scenario is a two-column list**, not two screens: left column cycles (BODY rows: name, count, first release year), right column the chosen cycle's scenarios (BODY rows: set icon, name, pack, `n stages`). The first cycle is preselected so a scenario is one tap away.
- **R3 — `pick_scenario` opens the overview**; it no longer starts the game. `begin_setup` (overview CTA) starts it with the chosen difficulty. The three-tap path is cycle → scenario → Begin setup.
- **R4 — The in-play overview is read-only:** opened from the stage pill (`open_overview`), it shows the game's own difficulty (`game.scenario.mode`) as a static badge, no ladder, and its footer is `Close`. Same renderer, `ui.overview.readonly = true`.
- **R5 — "This scenario's own set as card images with counts"** = every card in `bundle.scenario.encounter.*` groups whose `encounterSet === scenario.name`, grouped by type (enemy, location, treachery, objective…) in that order, each `cardImage` captioned `name · ×quantity` plus the printed values the picker already formats for locations (threat/points) and for enemies (engagement/threat/attack/defence/hit points from the face). Shared sets (`includedSets` minus the own set) render as chips with their set icon; tapping one is not a feature this milestone.
- **R6 — `TIP_TEXT` moves to `viewcopy.py` as `MODE_TIPS = {"Easy": …, "Nightmare": …}`** (verbatim), regenerated into `viewcopy.js`; `screens_other.js` imports it; the Python options screen reads it. The generic fallback sentence (`"%s: follow this quest's %s Mode card."`) moves with it as `MODE_TIPS_FALLBACK`.
- **R7 — Stages with points:** each stage row shows `Stage n` + the back face's name + points via `stagePointsShape` (number / the card's X text / nothing — never a 0 the card did not print), and for a branch stage one sub-row per alternative.
